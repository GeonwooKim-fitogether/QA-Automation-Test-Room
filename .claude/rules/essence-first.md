# 본질 우선 규칙 — 화면보다 규칙 한 줄이 먼저다

> 한 줄 요지: **기획·화면·코드를 만들기 전에, 그 일의 규칙을 식 한 줄로 쓰고 실제 같은 숫자로 끝까지 계산해 보인다.** 한 줄로 안 써지면 아직 이해하지 못한 것이다. 사용자가 "이게 뭐지?"라고 물으면 문구를 고치지 말고 규칙을 의심한다.

## 1. 순서

| # | 할 일 | 통과 기준 |
|---|---|---|
| 1 | 규칙을 식 한 줄로 쓴다 | 설명 없이 식만 보고 계산할 수 있다 |
| 2 | 예시 숫자로 끝까지 계산한다 | 0·빈칸·"…" 없이 최종값까지 나온다 |
| 3 | 사용자에게 식과 예시를 먼저 확인받는다 | 화면 시안보다 앞 |
| 4 | 화면은 그 식을 그대로 그린다 | 식에 없는 칸은 화면에도 없다 |

## 2. 한 가지 기준

- **값의 주인은 하나다.** 같은 개념을 두 자리에 두지 않는다.
- **상위는 하위를 합치고, 자기 것만 붙인다.** 하위 값을 상위가 다시 계산하지 않는다.
- **가장 단순한 한 기준을 먼저 제안한다.** 종류를 나누고 선택지를 늘리는 것은 그 기준이 실제로 안 맞을 때만.

## 3. 칸 검사

화면의 칸마다 두 가지를 한 마디로 답한다. 못 하면 칸을 빼거나 규칙을 고친다.

| 질문 | 예 |
|---|---|
| 이 값은 누구의 것인가 | 이 품목 |
| 어디에 붙는가 | 이 품목의 원가 |
| 단위가 맞는가 | 더하는 값끼리 같은 단위(원 + 원). %는 금액으로 바꿔서 보인다: `9,500 + 190 (2%) = 9,690` |

## 4. 멈춤 신호

| 신호 | 할 일 |
|---|---|
| 사용자가 "이게 뭐지?", "이게 말이 돼?" | 문구 수정 금지. 1절 1번으로 돌아간다 |
| 같은 화면을 두 번 반려 | 화면 수정 금지. 규칙을 한 줄로 다시 쓴다 |
| 칸을 설명하려고 문장이 필요하다 | 규칙이나 배치가 틀렸다 |
| 예시에 0·빈칸이 있다 | 예시를 채우기 전에는 보여 주지 않는다 |

## 5. 태어난 사고 (2026-11-11, FitOps 표준원가 Loss율)

| 틀린 것 | 맞는 것 |
|---|---|
| 조립품의 Loss율을 "상위 품목에 들어갈 때" 붙임 | 품목마다 Loss율 하나, 자기 원가에 붙임 |
| 화면에 Loss 칸이 두 군데 | 식 안의 한 칸 |
| 사용자 질문 네 번에 문구·배치만 고침 | 규칙이 틀렸음 |
| 예시 화면의 재료비·Loss 가 0 | 숫자를 채워 계산 과정을 보임 |
| 부품 Loss·조립 Loss 두 종류로 나누자고 제안 | 한 기준으로 충분 |
| 시안에 `9,500 + Loss 2%` (원 + %) | `9,500 + 190 = 9,690` (원 + 원) |

사용자가 준 규칙:

```
원자재  원가 = 단가 × (1 + Loss율)
조립품  원가 = (하위 원가 합 + 가공비) × (1 + Loss율)
```
