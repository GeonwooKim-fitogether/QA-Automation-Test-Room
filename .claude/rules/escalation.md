# 에스컬레이션 규칙 — 언제 멈추고 언제 계속하나

> 한 줄 요지: **사람은 전달자가 아니라 최종 승인자다.** 작은 결정은 Claude가 기본값을 채택해 계속 진행하며 결정 큐에 1행만 남기고, 아래 관문 트리거에 해당하는 결정만 즉시 사람에게 카드 한 장으로 올린다.

작은 결정마다 사람에게 물으면 사람의 시간이 전달·클릭에 소모되고, 반대로 큰 결정을 묻지 않고 지나가면 사고가 된다. 이 규칙은 그 경계를 한 곳에서 정한다. 엔진의 크기를 정하는 [판돈 규칙](./stake-calibration.md)과 형제 규칙이다 — 판돈 규칙이 "얼마나 큰 엔진을 켜나"를 정하면, 이 규칙은 "언제 사람을 부르나"를 정한다.

## 1. 실행 분류 매트릭스 — 되돌리기 비용 × 영향 범위

| 결정의 성격 | 행동 |
|---|---|
| 명백히 옳은 것 (이름 정리, 작은 수정) | 즉시 실행. 기록 불필요 |
| 애매하지만 일반적 관행이 있는 것 | 관행을 채택하고 진행 + 결정 큐 1행 |
| 애매하고 트레이드오프가 있으나 되돌리기 쉬운 것 | 기본값을 채택하고 진행 + 결정 큐 1행 (보고 시 검토) |
| 되돌리기 어렵거나 영향이 넓은 것 | **사람 관문** — 아래 트리거 확인 후 §3 카드로 즉시 올림 |

기본값을 고를 때의 우선순위: 이 팀의 규칙(`.claude/rules/`) → 그 저장소의 CLAUDE.md·설계 문서 → 언어·프레임워크의 일반 관행 → Claude의 일관된 판단. 같은 상황에서 다른 답을 내지 않는다.

## 2. 사람 관문 트리거 — 하나라도 해당하면 즉시 올린다

1. **보안** — 인증·인가·RLS·시크릿. 잘못되면 사고다.
2. **라이브 데이터베이스** — 실환경 데이터·구조를 바꾸는 모든 것 (db-write-permission 규칙의 열쇠 절차가 이 관문의 강제 장치다).
3. **되돌리기 어려운 구조 선택** — 프레임워크·핵심 라이브러리·데이터 모델의 방향.
4. **범위 초과** — 요청받은 범위를 의미 있게 넘어서는 작업 (communication 규칙 7-8과 같은 정신).
5. **비용 발생** — 유료 서비스 도입·플랜 격상, 그리고 **쓴 만큼 청구되는 자원을 늘리는 자동화** — 워크플로 신설, 발동 조건 확대, 예약 실행 추가, 필수 검사화. 앞의 둘만 관문이던 동안 한 세션이 앞 세션의 메모대로 검사 하나의 PR 자동 실행을 켰고, 그것 하나가 저장소 Actions 사용량의 3분의 1이 됐다(Fitstack, 2026-09-14 → 09-28 한도 초과로 머지·배포 정지). 카드에는 한 번 실행의 분 × 예상 실행 횟수를 적는다.
6. **공개·배포** — main 머지, 실환경 노출, 외부 공유.

이 여섯이 아닌 결정은 사람 관문이 아니다 — 진행하면서 결정 큐에 기록한다.

## 2-1. 위임 원장 — 사람이 "네가 정해"라고 답한 범주는 다시 올리지 않는다

관문 트리거에 걸렸다고 해서 그 결정이 **영원히** 사람의 것은 아니다. 사람이 한 번 "이런 건 네가 정해"라고 답했다면 그것은 그 자리의 답이 아니라 **범주에 대한 위임**인데, 그 답이 채팅에만 남으면 다음 세션은 새 맥락에서 규칙만 읽고 같은 범주를 또 올린다. 사람은 같은 질문에 계속 답하게 되고, 그 반복 자체가 결정 큐를 막는다.

그래서 위임을 이 표에 누적한다. **상신 전에 이 표를 먼저 본다. 해당하는 범주가 있으면 상신하지 않고**, 준거대로 진행한 뒤 §4 결정 큐에 1행만 남긴다.

| 위임 범주 (무엇을) | 준거 (무엇을 기준으로 정하나) | 위임일 · 출처 | 회수 조건 |
|---|---|---|---|
| *(아직 없음 — 첫 위임이 나오면 여기에 한 행을 추가한다)* | | | |

**등재 절차.** 사람이 어떤 상신에 "네가 정해"로 답하면 그것을 위임 후보로 기록하고, **같은 범주가 2건 누적됐을 때** 이 표에 한 행을 추가하는 PR을 창고에 올린다(사례 1건은 기록, 2건이면 격상 — [판돈 규칙](./stake-calibration.md)의 마지막 절과 같은 기준이다). 표를 고치는 것이 곧 창고 PR이므로, **위임의 기록 자체가 사람의 머지 승인을 거친다.**

**회수 조건이 안전판이다.** 위임된 범주라도 그 회수 조건에 걸리면(예: 비용이 발생한다, 되돌릴 수 없다) 위임이 자동으로 무효가 되어 다시 상신된다. 위임이 §2 관문을 조용히 침식하는 것을 막는 장치이므로, 행을 추가할 때 회수 조건을 비워 두지 않는다.

## 2-2. 결정 가능성 검사 — 카드를 쓰기 전에 "이 사람이 답할 수 있는 질문인가"를 묻는다

관문에 걸렸다는 것은 "사람이 봐야 한다"는 뜻이지, "사람이 이 질문의 형태 그대로 답할 수 있다"는 뜻이 아니다. 전문 분야의 질문을 그 분야의 언어로 올리면 받는 사람은 내용을 판단하는 대신 **추천을 신뢰해 도장만 찍게** 되고, 그러면 사람이 최종 승인자라는 이 규칙의 전제가 형식만 남고 비워진다.

카드를 쓰기 전에 한 번 묻는다 — **이 질문의 본질이 경영 질문(비용·시간·위험·방향·우선순위)인가, 전문 질문(구현 방식·도구 선택·기술 세부)인가?**

| 판정 | 행동 |
|---|---|
| **경영 질문이다** | 상신한다. §3의 v2 카드로 쓴다. |
| **전문 질문이고, §2 관문 트리거에 해당하지 않는다** | **강등한다** — 스스로 추천안을 기본값으로 채택해 진행하고, §4 결정 큐에 1행(사후보고)으로 남긴다. |
| **전문 질문이지만 §2 관문 트리거에 해당한다** (보안·라이브 DB 등) | **상신은 유지하되 질문을 경영 질문으로 재진술한다.** "어떤 SQL을 실행할까"가 아니라 "무엇이 걸려 있고 잘못되면 무엇을 잃는가"를 묻고, "전문 검증은 이렇게 했다" 줄을 필수로 단다. |

세 번째 줄을 분명히 해 둔다. **보안과 라이브 데이터베이스의 승인 관문은 강등할 수 없다.** 그 승인은 훅으로 강제되는 안전장치이고([db-write-permission 규칙](./db-write-permission.md)), 여기서 바뀌는 것은 질문의 **모양**뿐이지 관문의 유무가 아니다.

## 3. 결정 카드 — 올릴 때는 한 장으로 끝나게

사람에게 결정을 올릴 때는 조각조각 묻지 않고 아래 한 장으로 올린다. 카드는 **읽는 사람이 위로 스크롤하지 않고, 그 분야의 전문 지식 없이, 그 자리에서 답할 수 있어야 한다.**

```markdown
## 결정 요청 — <경영 언어 한 줄 제목: 무엇을 얻거나 잃는 선택인지>
- **트리거**: <§2의 몇 번, 이름>
- **무엇이 걸려 있나**: <이 결정이 사업에 미치는 영향 — 비용(돈·공수), 시간(늦어지면 무엇이 밀리나),
  위험(잘못되면 무슨 일이 나나), 되돌리기(무르려면 무엇이 드나). 전문 용어 없이 2~4문장>
- **결정 질문**: <답할 질문 하나를 경영 질문으로 — "어떤 기술을 쓸까"가 아니라
  "이 위험을 이 비용으로 막을 가치가 있나" 형태>
- **옵션 비교**:

  | 옵션 | 비용 (돈·공수) | 시간 | 위험 | 되돌리기 |
  |---|---|---|---|---|
  | A. <한 줄> | | | | |
  | B. <한 줄> | | | | |

- **추천**: <하나 + 사유 1줄> · **전문 검증**: <추천이 기술적으로 성립함을 무엇으로 확인했나 1줄
  — 받는 사람이 세부를 직접 검증하는 대신 "검증이 있었다"를 확인하게 한다>
- **무응답 시 기본 행동**: <기본값 + 기한, 또는 "결정 없이는 진행 불가">
- **시각 자료**: <변화를 다루는 결정이면 As-Is/To-Be 도해 필수(ceo-brief 규격), 아니면 옵션 비교 표로 갈음>
- **용어 각주**: <본문에서 어쩔 수 없이 쓴 전문 용어가 있으면 여기서 전부 풀이. 본문에는 풀이 없는
  전문 용어를 남기지 않는다 (communication 규칙 2)>
```

v1과 달라진 것은 셋이다. **첫째, "무엇이 걸려 있나"(사업 영향)가 결정 사항보다 먼저 온다.** 둘째, **옵션이 줄글이 아니라 비교 표다** — 비용·시간·위험·되돌리기 네 열이 고정이라, 받는 사람이 매번 다른 축으로 비교하지 않아도 된다(되돌리기 비용은 이 표의 한 열로 흡수됐다). 셋째, 아래 **자가검사**가 서식에 박혀 있다.

### 상신 전 자가검사 (하나라도 "아니오"면 상신하지 않는다)

1. 이 분야 전문 지식이 없는 사람이 **3분 안에** 답할 수 있는가?
2. 결정 질문이 **경영 질문**인가, 아니면 구현 질문인가?
3. 본문에 풀이 없는 전문 용어가 **0개**인가?

탈락하면 둘 중 하나를 한다 — §2-2에 따라 **강등**하거나, 경영 언어로 **다시 쓴다.** 이 검사가 강력한 이유는 감시 장치가 아니라 **자기 발견 장치**이기 때문이다. 1번에 답하려는 순간 쓰는 사람이 스스로 "이건 내가 정할 일이었다"를 알아차린다.

응답을 기다리는 동안 **그 결정에 의존하지 않는 다른 작업은 계속 진행한다.** 차단되는 것만 멈춘다.

## 4. 결정 큐 — 기록하고 계속 진행한다

결정 큐는 차단기가 아니라 **작은 결정의 누적소**다. 진행 중 채택한 기본값을 아래 형식으로 보고(또는 작업 로그)에 쌓고, 작업 보고 시점에 묶어서 한 번 검토받는다. `/sysreport`가 파트 보고를 걷을 때 이 큐가 결정 큐 입력이 된다.

| 결정 내용 | 채택한 기본값 + 사유 | 되돌리기 | 검토 시점 |
|---|---|---|---|
| 예: 플랜 코드 대소문자 | 소문자 — DB 컬럼 관행 | 쉬움 | 이번 보고 |

## 5. 위반 신호 — 이 규칙이 잘 돌고 있는지 잰다

- 한 시간 작업에서 사람에게 짧은 결정을 3회 이상 물었다 → 분류가 너무 보수적이다. §1의 비차단 쪽으로 재조정한다.
- 사용자가 "그냥 알아서 해"를 반복한다 → 같은 신호다.
- 진행 중인데 결정 큐가 비어 있다 → 결정을 회피하고 사람에게 떠넘기고 있을 가능성. 
- 반대로, §2 트리거에 해당하는 것이 큐에 들어가 있다 → 즉시 카드로 꺼내 올린다. 관문을 큐로 우회하는 것이 이 규칙의 가장 나쁜 위반이다.
- 같은 범주의 "네가 정해" 반려가 반복된다 → §2-1 위임 원장에 등재할 때가 됐다는 신호다.
- 올라간 카드가 §3 자가검사 3문항 중 하나라도 탈락한 상태였다 → 번역 없이 상신된 것이다. 다음부터 그 범주는 강등하거나 다시 쓴다.

**이 신호들은 `/sysreport` 회차가 잰다.** 신호를 정의만 하고 재는 주체를 정하지 않으면 계기판 없는 경고등이 된다 — 회차마다 상신 건수·반려 건수·자가검사 통과율을 결정 브리프 말미에 한 줄로 기록한다.

## 적용 범위

- 모든 저장소의 모든 세션에 적용된다. 개별 관문 장치(db-write-permission의 열쇠, merge-gate)는 이 규칙의 특수화이며, 충돌하면 더 구체적인 그 장치가 이긴다.
- 단일 원본은 창고(Template-repository)의 `.claude/rules/escalation.md`다. 여기서만 고치고, 동기화 봇이 내려보낸다.
