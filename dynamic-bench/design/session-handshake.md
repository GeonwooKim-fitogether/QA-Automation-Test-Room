# 두 세션의 소통 규약 — 모터(메인)와 결과판이 유기적으로 가는 법

> 한 줄 요지: **모터 세션은 시험 · 판정 · 파일을 만들고, 결과판 세션은 그 파일을 읽어 화면을 만든다. 둘 사이의 약속은 파일 칸 하나로 고정하고, 바꿀 때는 먼저 알린 뒤 양쪽이 같은 커밋을 가리키게 한다.** 어느 쪽도 상대 폴더를 고치지 않는다.

2026-10-29 김건우 지시: 장비는 앞으로 계속 유기적으로 바뀌므로, 양쪽이 서로의 진행 상황을 확인하고 개선이 바로 반영되게 한다.

## 1. 누가 무엇을 맡나

| | 모터 세션 (`[제어PC2] 모터 · Dynamic Bench`, 작업 폴더 `C:\Dev\dynamic-bench`) | 결과판 세션 (`[제어PC2] 결과판 · 모터 화면`, 작업 폴더 `C:\Dev\QA-Automation-Test-Room`) |
|---|---|---|
| 만드는 것 | 시험 프로토콜, 모터 · 셀 · 시뮬레이터 실행, 판정 코드, 결과 파일 | 실시간 화면, 결과 화면, 비교 화면, 보고서 |
| 고치는 폴더 | `cell-bench/motionbench/`, `cell-bench/run_motion.py`, `cell-bench/tools/`, `dynamic-bench/`, `cell-bench/data/`(프로그램이 씀) | `cell-bench/board/`, `cell-bench/serve_board.py`, `cell-bench/docs/`, 결과판 브랜치 |
| 손대지 않는 것 | 결과판 폴더 | 모터 폴더와 실제 `cell-bench/data/` (시험용 가짜 파일은 스크래치 폴더에) |
| 브랜치 | `feat/m4-cell-compare` (PR #22) | `feat/rail-qc-board` (PR #24) |

## 2. 둘 사이의 약속은 파일 칸 하나

약속의 정본은 **프로토콜 문서의 "결과판에 넘길 것" 절**(지금은 [`qc-protocol-v4.md`](qc-protocol-v4.md) 7절)이다. 거기에 적힌 것만 결과판이 읽는다.

| 파일 (`cell-bench/data/` 바로 아래) | 쓰는 쪽 | 읽는 쪽 | 언제 |
|---|---|---|---|
| `qc_now.json` | 모터 세션의 실행 프로그램 | 실시간 화면 | 시험 중 1초마다 덮어씀 |
| `protocol_<시각>.json` · `.csv` | `tools/protocol_report.py` | 결과 · 비교 화면 | 시험 뒤 1개 |
| `scene_<이름>.csv` | `tools/scene_gen.py` | 결과 화면(장면 정답) | 장면을 만들 때 |
| `sim_bridge_<시각>.csv` | `motionbench/sim_bridge.py` | 분석(동기 지연) | 파트 B 시험 중 |
| `compare_<모터 기록>.csv` | `tools/compare_motion_cell.py` | 성능 비교 화면(기존 약속 `docs/perf-results.md`) | 시험 뒤 |

칸의 뜻과 이름은 문서가 정본이고, 판정은 모터 세션의 `qc_protocol.py` 가 정본이다. 결과판은 판정을 다시 계산하지 않는다.

## 3. 바꿀 때의 순서 — 알리고, 적고, 같은 커밋을 가리킨다

1. **먼저 알린다.** 칸을 더하거나 이름을 바꾸거나 뜻을 바꾸려는 쪽이 상대 세션에 세션 메시지로 보낸다: 무엇을 왜 바꾸나, 언제부터 파일에 찍히나, 옛 칸은 언제까지 남기나.
2. **문서에 적는다.** 모터 세션이 프로토콜 문서의 "결과판에 넘길 것" 절을 고치고 커밋한다. 커밋 제목에 `docs:` 와 바뀐 칸 이름을 적는다.
3. **파일에 판을 찍는다.** `protocol_*.json` 과 `qc_now.json` 의 `conditions.protocol`("v4" 등)과 `judge_commit`(판정 코드 커밋)으로 결과판이 어느 판의 파일인지 안다. 결과판은 모르는 판이면 "이 판은 아직 지원 안 함"을 보이고 멈추지 않는다.
4. **옛 칸은 한 판 동안 남긴다.** 이름을 바꾸면 새 이름과 옛 이름을 한 판 동안 둘 다 찍어, 결과판이 따라올 시간을 준다.
5. **결과판이 바꾸고 싶은 것**(새 화면에 필요한 값 등)은 결과판 세션이 모터 세션에 요청하고, 모터 세션이 1~4 를 한다. 결과판이 모터 폴더를 직접 고치지 않는다.

## 4. 서로의 진행 상황을 보는 법

- **세션 메시지**가 기본 통로다. 각 세션은 시험 하나를 끝내거나 화면 하나를 올릴 때마다 상대에게 한 줄을 보낸다: 무엇이 됐나, 어느 커밋 · PR 인가, 상대가 이제 할 수 있는 것이 무엇인가.
- **열린 PR 두 개가 진행판이다.** PR 본문의 "보는 법"(어디서 · 무엇을 하면 · 무엇이 보이나)을 각자 최신으로 유지한다. 상대 PR 을 읽으면 진행이 보인다.
- **시험 기록은 README 7절 표**, 결정은 이 폴더의 `design/` 문서다. 결과판 세션은 새 일을 시작하기 전에 README 7절의 마지막 행과 프로토콜 문서의 상태 줄을 읽는다. 모터 세션은 결과판 PR 본문을 읽는다.
- **메모리**는 두 세션이 같은 폴더를 읽는다(`~/.claude/projects/C--Dev-QA-Automation-Test-Room/memory/`). 경계 · 역할 · 오늘 결정은 거기 `session-roles` · `tomorrow-*` 에 적는다. 메모리는 요약이고 정본은 저장소 문서다.

## 5. 충돌하면

- 같은 파일을 둘이 고쳐야 할 때(`bench.json`, `requirements.txt`, 루트 README)는 먼저 메시지로 합의한 뒤 한쪽만 고친다.
- 결과판 화면에 필요한 값이 판정 파일에 없으면, 결과판은 그 칸을 "이 시험에 없음"으로 보이고 모터 세션에 요청한다. 임시로 결과판이 계산해 넣지 않는다.
- 사용자 지시가 한쪽 세션에만 들어오면, 받은 쪽이 상대에게 전달한다. 전달할 때 사용자의 말을 그대로 인용한다.

## 적용 범위

이 문서는 모터 세션이 관리한다(결과판 세션이 고치고 싶으면 요청). `dynamic-bench/README.md` 와 메모리 `session-roles` 에서 링크한다.
