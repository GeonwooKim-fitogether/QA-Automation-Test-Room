# 사내 공통 화면 기준 v1 — Fitogether 사내 웹앱은 같은 색·서체·배지로 그린다

> 한 줄 요지: **Fitogether 사내 웹앱(Fitstack·FitOps·FitDeal, 앞으로 만들 앱 포함)의 화면은 아래 값으로 그린다.** 누르는 것과 고른 것은 잉크(#0a1316), 링크와 작은 표식은 진한 청록(#12747e), 상태는 일곱 톤의 채운 배지다. **개인용 작업에는 이 기준을 강요하지 않는다.** 2026-11-06 에 사용자가 그림을 보며 항목을 하나씩 확정했고, Fitstack 에는 2026-11-07 에 배포됐다.

이 기준은 회사의 브랜드 문서 가이드를 **앱 화면에 맞게 골라 쓴 것**이다. 사내 시스템이 늘면서 같은 회사의 앱인데 겉모습이 서로 달랐고, 한 앱 안에서도 같은 뜻의 상태가 화면마다 다른 색이었다(예: "진행 중"이 어떤 화면은 파랑, 어떤 화면은 호박색). 결정 경위와 Fitstack 적용 때 난 사고는 [부록](./reference/fitogether-ui-standard-history.md)에 있다.

## 1. 언제 적용하나

| 작업 | 적용 |
|---|---|
| Fitogether 사내 웹앱의 화면을 만들거나 고친다 (Fitstack·FitOps·FitDeal, 새 사내 앱) | **적용한다** |
| 개인용 화면·문서·실험 | 강요하지 않는다. 쓰고 싶으면 써도 된다 |
| 어느 쪽인지 모른다 | 착수 전에 사용자에게 묻는다. 묻는 일은 KimLead(`/orchestrate`)가 맡고, 사용자에게 물을 수 없는 서브에이전트는 저장소 원격이 `fitogether-org` 인지로 추정한 뒤 그 추정을 반환에 적는다 |

화면 작업의 순서(시안을 먼저 보여 주고 확인받은 뒤 개발)와 시안 형식은 [`orchestrate.md`](../commands/orchestrate.md) 5-2절이 정한다.

### 상태 배지 — 일곱 톤, 채움

상태는 **뜻으로 톤을 고른다.** 배지는 테두리 없이 바탕을 채우고, CSS 변수 이름은 FitOps 를 따라 바탕 `--tone-<톤>`, 글자 `--tone-<톤>-fg` 다.

| 톤 | 뜻 | 바탕 | 글자 |
|---|---|---|---|
| `neutral` | 대기 | `#e0e5e8` | `#35434c` |
| `info` | 작성 · 등록 | `#d4e2fb` | `#1f4288` |
| `accent` | 접수 · 확정 | `#cceaf0` | `#0b5a6b` |
| `progress` | 진행 | `#fce0c8` | `#96450c` |
| `success` | 완료 | `#cbe9cf` | `#1b6b3c` |
| `warning` | 주의 | `#f8e8b6` | `#6b5104` |
| `danger` | 위험 · 취소 | `#fbdada` | `#a72f2f` |

- **취소·철회·포기는 `danger` 다.** 회색으로 두면 "아직 안 한 것(대기)"과 구별되지 않는다.
- **분류 꼬리표는 상태가 아니므로 톤에 넣지 않는다.** 그룹·제품군·품목 종류 같은 꼬리표는 각자의 색을 유지한다. 분류를 상태 톤으로 칠하면 "완료된 Dock"처럼 읽힌다.

### 앱마다 그대로 두는 것

- **화면 틀과 메뉴 방향** — 각 앱의 지금 배치를 유지한다.
- **아이콘** — Fitstack 은 antd, FitOps 는 Remix. 앱을 넘나들며 통일하지 않는다.
- **메뉴 언어** — 앱마다 한 언어로 맞춘다. Fitstack 은 영어, FitOps 는 한국어다.

### 폐기한 것

- **Fitstack 의 Ground Control 테마**(어두운 청록·형광 시그널·종이색 바탕). 이 기준보다 먼저 쓰인 문서가 Ground Control 을 정본이라고 하면 이 규칙이 이긴다.

## 3. 이번에 정하지 않은 것

**글자 크기 하한, 다크 모드, 차트 색, 문구 말투**는 v1 에서 정하지 않았다. 이 넷은 각 앱의 지금 방식을 그대로 두고, 새로 정해야 하면 사용자에게 그림을 보여 주며 묻는다. 정한 결과는 이 파일을 v2 로 고쳐 남긴다.

## 4. 앱별 정본 위치

값은 이 규칙이 정하고, **"어느 상태가 어느 톤인가"의 배정과 코드에서 값을 받는 자리**는 각 앱의 정본이 정한다. 둘이 어긋나 보이면 조용히 한쪽에 맞추지 말고 사용자에게 알린다.

| 앱 | 정본 |
|---|---|
| Fitstack | `docs/design-tokens.md` 첫 절(「사내 공통 화면 기준 v1」), 상태별 톤 배정은 `app/src/lib/ui/statusTone.ts` |
| FitOps | `src/app/globals.css` 의 `--tone-*` 변수, 배지는 `src/components/ui/status-badge.tsx` |
| FitDeal | 아직 적용 전이다. 적용하면 이 표에 한 줄 더한다 |

## 5. 지키게 하는 장치

**색 리터럴 톱니 검사** — Fitstack 의 `app/src/lib/color-literal.guard.test.ts` 가 단위 검사마다 돈다. 화면 코드에서 색을 직접 적은 곳(`#rrggbb`·`rgb()` 등)을 파일별로 세어 기준선(`app/src/lib/color-literal.baseline.json`)과 비교하고, **어느 파일에서든 늘면 실패한다.** 새 파일의 기준선은 0 이라 새 화면은 처음부터 토큰만 쓰게 되고, 줄어든 것은 기준선을 낮추라고 안내만 한다. 색 값을 정의하는 파일(토큰 파일·테마·톤 표)은 세지 않는다. 정말 색을 직접 써야 하면 기준선을 갱신하고 그 이유를 PR 본문에 적는다.

- **토큰을 지우거나 이 검사를 새로 넣는 PR 은, 머지 전에 같은 토큰·화면을 만지는 열린 PR 이 있는지 확인하고 그쪽에 알린다.** 두 PR 이 각자의 base 에서는 초록이어도 차례로 머지되면 main 이 빨개지고 배포가 멈춘다 — Fitstack 에서 2026-11-07 에 실제로 일어났다(부록).
- **이 검사가 잡지 못하는 것.** 검사는 색을 직접 적은 횟수만 센다. 토큰을 잘못 고르는 것(예: 링크 색을 버튼에 쓰기)과 서체·모서리·그림자 이탈은 잡지 못하므로, 그것은 시안 확인과 리뷰에서 본다.
- **지금 이 검사는 Fitstack 에만 있다.** FitOps·FitDeal 에 넣을지는 그 앱에 기준을 적용하는 작업에서 정한다.

## 적용 범위

- Fitogether 사내 웹앱의 화면 작업에 적용된다. 이 파일은 모든 저장소에 내려가 세션마다 읽히지만, 개인용 작업에서는 1절에 따라 적용하지 않는다.
- 단일 원본은 창고(Template-repository)의 `.claude/rules/fitogether-ui-standard.md` 다. 기준을 바꾸는 결정은 사용자가 그림을 보며 하고, 바뀐 값은 여기서 고쳐 동기화로 내려보낸다.
