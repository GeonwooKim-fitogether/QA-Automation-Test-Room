# 셀 QC 시험 목록

> **문서 판 2.1 · 2026-11-13**
> 레일 QC 의 시험 이름 · 조건 · 절차 · 합격 기준을 이 문서 하나에 모은다. 문서와 화면에는 한글 이름(GNSS-정지 등)을, 코드 · 파일 · 폴더에는 영문 ID(`GNSS-STATIC` 등)를 쓴다. 합격 기준은 시험마다 버전 번호(0.1 · 0.2 …)를 붙여 고쳐 나간다.
> 저장소의 코드 · 프리셋 · 기준 파일 · 실행기도 이 ID 만 쓴다(2026-11-13 사용자 결정 — 옛 ID 와의 대응은 4절 바뀐 이력). 옛 문서 [프로토콜 v4](qc-protocol-v4.md)는 폐기했다. 판정 파일의 칸 이름만 아직 그 문서의 약속을 따른다.

## 1. 시험 여섯 가지

이름은 **센서(GNSS · IMU)** 와 **층(정지 · 이동 · 펌웨어)** 을 함께 드러낸다(2026-11-13 사용자 결정). 정지 · 이동은 센서가 낸 Raw data를, 펌웨어는 셀 펌웨어를 거친 값을 본다. 차례는 GNSS 셋, 그다음 IMU 셋이다.

| 시험 | 영문 ID | 옛 ID(2026-11-12) | 판정 대상 | 불합격이면 볼 곳 | 모터 | 검증 상태 |
|---|---|---|---|---|---|---|
| **GNSS-정지** | `GNSS-STATIC` | GNSS-1 | GNSS 센서 출력(신호 세기) | 안테나 · 수신 회로 | 없음 | 검증 중 |
| **GNSS-이동** | `GNSS-MOVE` | GNSS-2 (11-12 전에는 FIRMWARE-2) | GNSS 센서 출력(GPS Raw data 속도 · 위치) | GNSS 수신 모듈 | 있음 | 검증 중 |
| **GNSS-펌웨어** | `GNSS-FW` | FIRMWARE-2 | 펌웨어 산출값(IMU 판정을 거친 속도로 더한 거리) | 펌웨어의 속도 · 거리 계산 | 있음 | 보류 |
| **IMU-정지** | `IMU-STATIC` | IMU-1 | IMU 센서 출력 | IMU 칩 · 보정값 | 없음 | 검증 중 |
| **IMU-이동** | `IMU-MOVE` | IMU-2 | IMU 센서 출력 | IMU 칩 · 보정값 | 있음 | 가설 |
| **IMU-펌웨어** | `IMU-FW` | FIRMWARE-1 | 펌웨어 산출값(IMU 움직임 판정) | 펌웨어의 IMU 움직임 판정 | 있음 | 가설, 프로토콜 설계 중 |

- **센서 출력**: 센서 칩이 낸 값 그대로(셀 저장 기록의 GNSS 원래 속도 · 위치 · 신호 세기, IMU 가속도 · 각속도). GPS Raw data는 펌웨어가 손대지 않으므로 GNSS-이동은 펌웨어가 아니라 GNSS 수신 모듈을 보는 시험이다.
- **펌웨어 산출값**: 셀 펌웨어가 센서 출력으로 계산한 값(IMU 움직임 판정, 그 판정을 거친 속도, 그 속도로 계산한 거리). Live 앱이 따로 계산하는 거리는 이 목록의 대상이 아니다.
- 시험마다 운전이 다르다. 여러 시험을 이어 돌릴 때는 묶음 실행기가 준비(장면 · 플러그 · 위치 잡기)와 셀 기록 받기를 한 번으로 줄인다(아래 "실행기와 판정 스크립트").

**QC · QA 나눔** (2026-11-13 사용자 결정)

| 구분 | 시험 | 대상 | 언제 |
|---|---|---|---|
| QC | GNSS-정지 · GNSS-이동 · IMU-정지 · IMU-이동 | 셀 전부 | 셀마다 합격 · 불합격 |
| QA | 펌웨어 시험 (GNSS-펌웨어 · IMU-펌웨어를 하나로 본다) | 셀 몇 대 | 펌웨어 버전마다 1회 |

- 근거(셀 펌웨어 소스 0.99.71): IMU 움직임 판정은 0.1초마다 가속도 10개 크기의 표준편차가 7.0 을 넘는지로 정한다. IMU 판정을 거친 속도는 최근 0.5초 GPS Raw data 속도의 가중 평균이고, '움직임 아님' 표본은 더하지 않는다. 같은 펌웨어 버전 · 같은 저장 설정 · 센서 합격이면 이 값들은 셀을 가르지 못한다.
- QA 의 이름과 프로토콜(쓰는 QC 시험 · 셀 수 · 자리 · 횟수 · 보는 값 · 합격 기준)은 **논의 예정**이다. 아래 3절의 IMU-펌웨어 · GNSS-펌웨어 내용은 그때까지 참고로 둔다.
- 운전-가속 · GPS-동기 장면은 만들지 않는다. 움직이는 장면은 운전-등속용 6개만 만든다.
- IMU-이동은 운전-등속 기록과 합치지 않고 **운전-가속으로 따로** 한다(안정화 뒤 다시 검토).

**목적 · 목표** (2026-11-13 사용자 확인)

| 시험 | 목적 (검출 대상) | 목표 (판정) |
|---|---|---|
| GNSS-정지 | 안테나 · 수신 회로 약한 셀 | 같은 신호를 약하게 받는 셀 불합격 |
| GNSS-이동 | 속도 · 위치 오차 큰 수신 모듈 | 속도 6단계 GPS Raw data 속도 · 위치 합격 · 불합격 |
| GNSS-펌웨어 | 최종 속도 · 거리 오차 큰 셀 | IMU 판정 거친 속도 · 거리 대 GPS Raw data 합격 · 불합격 |
| IMU-정지 | 영점 틀어진 IMU | 정지 영점 오차 · 중력 크기 합격 · 불합격 |
| IMU-이동 | 가속도 측정 오차 큰 IMU | 가속도 9단계 속도 변화 비 합격 · 불합격 |
| IMU-펌웨어 | 움직임 판정 지연 · 오판 셀 | 가속도 9단계 판정 비율 · 지연 합격 · 불합격 |

**용어** — 셀 펌웨어는 IMU 가속도 크기의 흔들림(표준편차가 7.0 을 넘는가)으로 셀이 움직이는지 판단하고, 움직임으로 판단할 때만 GPS 속도를 통과시킨다.

| 용어 | 뜻 |
|---|---|
| IMU 움직임 판정 | 위의 펌웨어 판단. 결과는 '움직임' 또는 '움직임 아님'이다. GPS 기록마다 판정 값이 함께 남는다. IMU 기록이 0.01초 값(0x0E)이냐 0.1초 평균(0x0F)이냐는 **이 판정과 다른 기준**(이웃 표본 차이 문턱)으로 정해진다(펌웨어 소스 0.99.71) |
| IMU 판정을 거친 속도 | IMU 움직임 판정이 '움직임 아님' 이면 0 이 되는 GPS 속도(셀 기록의 `filtered_sog`). GNSS-펌웨어의 대상이다 |
| GPS Raw data 속도 | 판정을 거치지 않은 GPS 수신 모듈의 속도(라이브 패킷 · 셀 기록의 `sog`). GNSS-이동의 대상이다 |

**검증 상태 세 단계**

| 상태 | 뜻 |
|---|---|
| 보류 | 시험이 필요하다는 것은 정했지만 운전 · 장면이 준비되지 않아 지금은 돌리지 않는다. 실행기도 없다 |
| 가설 | 절차와 기준을 글로 세웠고 아직 실측으로 확인하지 않았다 |
| 검증 중 | 정상 셀로 절차가 재현되는 것을 확인했고, 불량 셀을 잡아내는지(검출력)가 남았다 |
| 확정 | 정상 셀의 반복성과 불량 셀 검출을 모두 실측으로 확인했다 |

## 1-1. 조건 모듈 — 한 칸에 조건 하나

시험 조건은 모듈 여섯 개로 나누고, **시험은 모듈 값의 조합으로 정의한다**(2026-11-13 사용자 결정). 조건 하나를 바꾸면 그 모듈 칸만 바뀐다. 실행기는 기록 폴더의 `summary.json` 에 **실제로 쓴 값**을 모듈마다 한 칸씩(`run` · `src` · `sat` · `gps` · `att` · `dock`) 적는다.

| 모듈 | 값 | 영문 ID | 뜻 |
|---|---|---|---|
| 운전 (`run`) | 운전-정지 | `RUN-STILL` | 레일 정지 |
| | 운전-가속 | `RUN-ACCEL` | 등속 구간 없이 가속도 단계를 올렸다 내리는 왕복 |
| | 운전-등속 | `RUN-CONST` | 1,500 mm 구간을 속도 단계별로 등속 왕복 |
| 신호원 (`src`) | 신호-LabSat | `SRC-LABSAT` | GNSS 시뮬레이터 LabSat 3 이 장면 파일을 재생해 독 쪽으로 방사한다 |
| | 신호-야외 | `SRC-SKY` | 야외의 실제 하늘 |
| 위성 구성 (`sat`) | 위성-12 | `SAT-12` | 위성 12개로 일정. 지금은 정지 장면 `S01-Static-GLE-8h` 의 313 ~ 357분 구간에만 있다 |
| | 위성-6 | `SAT-6` | 위성 4 ~ 6개. 지금의 움직이는 장면 셋(`S03_RailB120` · `S04_RailB100` · `S05_RailB500`) |
| | 위성-하늘 | `SAT-SKY` | 야외. 회차마다 위성 수를 기록한다 |
| GPS 움직임 (`gps`) | GPS-정지 | `GPS-STILL` | 한 자리 신호 |
| | GPS-동기 | `GPS-SYNC` | 장면이 레일 운전과 같은 움직임을 낸다 |
| | GPS-실제 | `GPS-REAL` | 야외. 셀의 실제 움직임 |
| 신호 세기 (`att`) | 감쇠-0 · 감쇠-18 · 감쇠-없음 | `ATT-0` · `ATT-18` · `ATT-NONE` | LabSat 출력 감쇠(dB). 야외는 감쇠가 없다 |
| 셀 배치 (`dock`) | 배치-12 | `DOCK-12` | 독 1 · 3행에만 12대(행 하나를 비워 앞 셀이 뒤 셀의 신호를 가리지 못하게) |
| | 배치-24 | `DOCK-24` | 독 전체 칸 |

**위성 수 근거** — 셀 기록(FTG)의 `navigation_satellites` 를 위치를 잡은 기록만 모아 하위 5 % · 중앙 · 상위 95 % 로 센 값이다(2026-11-13 집계).

| 장면 · 구간 | 위성 수(하위 5 % · 중앙 · 상위 95 %) | 근거 |
|---|---|---|
| `S01-Static-GLE-8h` 313 ~ 357분 | 12개로 일정 | 2026-11-11 실측 |
| `S01-Static-GLE-8h` 그 밖 구간 | 9 · 12 · 12 (2026-11-10 기록은 5 · 10 · 11) | 2026-11-12 |
| 움직이는 장면 셋 | 4 · 6 · 6 | `railB_20261110`(약 52만 건) · `railB_20261112_g1c`(약 12만 건) |

**공통 조건**(모듈이 아니고 모든 시험에 적용): 배터리 운전(충전 플러그 끔), 승인된 운전 값만 사용, 운전할 때 담당자 현장 입회.

## 1-2. 시험 = 모듈 조합 (실내 6 · 야외 3)

이 표가 시험 조건의 정본이다. 3절 각 시험의 '조건' 칸은 이 표의 조합을 가리킨다. **위성 구성 칸의 위성-12 는 목표값이다** — 실제로 위성-12 가 확보된 조합은 실내 GNSS-정지 하나뿐이고, 나머지는 칸 안에 기존 기록의 위성 수를 함께 적었다.

| 시험 | 장소 | 운전 | 신호원 | 위성 구성 | GPS 움직임 | 신호 세기 | 셀 배치 |
|---|---|---|---|---|---|---|---|
| GNSS-정지 | 실내 | 운전-정지 | 신호-LabSat | 위성-12 (확보 — 장면 313분부터 고정) | GPS-정지 | 감쇠-18 | 배치-12 |
| GNSS-이동 | 실내 | 운전-등속 | 신호-LabSat | 목표 위성-12 (제안 — 새 장면 뒤) · 기존 기록 위성-6 | GPS-동기 | 감쇠-0 | 배치-12 |
| GNSS-펌웨어 | 실내 | 운전-가속 | 신호-LabSat | 목표 위성-12 (제안 — 새 장면 뒤) · 기존 기록 없음 | GPS-동기 | 감쇠-0 | 배치-12 |
| IMU-정지 | 실내 | 운전-정지 | 신호-LabSat | 목표 위성-12 (장면 구간 고정 필요) · 기존 기록 9 ~ 14개 | GPS-정지 | 감쇠-0 | 배치-24 |
| IMU-이동 | 실내 | 운전-가속 | 신호-LabSat | 목표 위성-12 (장면 구간 고정 필요) · 기존 기록 위성 수 미집계(정지 장면을 처음부터 틀었음) | GPS-정지 | 감쇠-0 | 배치-12 |
| IMU-펌웨어 | 실내 | 운전-가속 | 신호-LabSat | 목표 위성-12 (장면 구간 고정 필요) · 기존 기록 8 ~ 12개 | GPS-정지 | 감쇠-0 | 배치-12 |
| GNSS-정지 | 야외 | 운전-정지 | 신호-야외 | 위성-하늘 | GPS-실제 | 감쇠-없음 | 배치-12 |
| GNSS-이동 | 야외 | 운전-등속 | 신호-야외 | 위성-하늘 | GPS-실제 | 감쇠-없음 | 배치-12 |
| GNSS-펌웨어 | 야외 | 운전-가속 | 신호-야외 | 위성-하늘 | GPS-실제 | 감쇠-없음 | 배치-12 |

- IMU 시험 셋은 야외 조합이 없다. IMU 시험이 쓰는 모듈(운전 · 셀 배치)이 실내와 같기 때문이다.
- 야외 회차마다 하늘 기록(시각 · 위성 수 · 신호 세기 · 날씨 · 주변 가림 · 독 방향)을 남기고, 같은 회차의 셀끼리만 비교한다.
- **지금까지의 GNSS-이동 기록(2026-11-10 · 11-12)은 위성-6 조합**이다(움직이는 장면 셋이 위성 4 ~ 6개). 위성-12 조합에는 새 장면이 필요하고, **새 장면을 위성-12 로 맞출지는 제안이며 사용자 결정 대기**다.
- **IMU 시험 셋의 위성-12 는 장면 구간을 고정해야 성립한다.** 지금 IMU 실행기는 정지 장면을 처음부터 틀거나(레일 준비) 건드리지 않아(IMU-정지) 위성이 8 ~ 14개로 흔들렸다. GNSS-정지처럼 장면 313분부터 트는 것은 **다음 작업**이다(이 판에서는 실행기를 고치지 않았다). 기존 기록의 위성 수(셀 기록 `navigation_satellites`, 위치 잡은 기록, 하위 5 % · 중앙 · 상위 95 %): IMU-정지 `imuStill_20261110` 9 · 11 · 14, IMU-펌웨어 `imuStep_20261112-1744` 정지 장면 구간 8 · 12 · 12.
- 기록의 `summary.json` 의 `sat` 칸에는 목표값이 아니라 **그 회차에 실제로 쓴 장면과 구간**을 적는다.
- **지금 실행기가 쓰는 값은 조합과 다를 수 있다** — 예를 들어 레일 실행기는 아직 꽉 찬 독(배치-24)으로 돌고, 정지 장면을 처음부터 틀어 위성 구성이 8 ~ 12개다. 기록의 `summary.json` 에 실제로 쓴 값이 남으므로, 결과를 볼 때는 그 칸을 본다.

## 1-3. 운전 단계 값 — 제안, 승인 대기

아래 값은 **제안이고 아직 승인되지 않았다.** 승인 프리셋 값은 바꾸지 않았다(지금 프리셋은 3절 시험마다 적었다).

| 운전 | 단계 (제안) | 미정 |
|---|---|---|
| 운전-가속 | 가속도 0.05 · 0.1 · 0.2 · 0.3 · 0.5 · 1 · 2 · 4 · 8 m/s² | — |
| 운전-등속 | 속도 0.1 · 0.3 · 0.5 · 1.0 · 1.4 · 2.0 m/s (구간 1,500 mm) · 가속도 8 m/s² (2026-11-13 사용자 승인) | — |

- **IMU-이동은 따로 운전하지 않고, 운전-가속 기록에서 가속도 단계마다 판정한다**(제안). 옛 IMU-이동 운전(긴 거리 0.3 m/s · 0.5 m/s², 프리셋 `IMU-MOVE_long`)은 이력으로 남긴다. 승인 전까지 실행기는 옛 운전으로 돈다.
- 운전-가속은 IMU-이동이 쓴다(QA 펌웨어 시험에서 쓸지는 논의 예정). 운전-등속은 GNSS-이동이 쓴다.

## 2. 공통 조건

- **세트**: 같은 구성의 셀 묶음(예: Y 세트 = CLBY-4B 23대). 한 시험 기록에는 세트 · 셀 펌웨어 판 · 독 배치를 남긴다.
- **배터리로 시험한다**: 독 플러그를 끄고 돌린다. 충전은 시험 사이에만 한다(2026-11-02 결정).
- **위성 신호**: 실내 GNSS 시뮬레이터 LabSat 3 의 장면을 독 쪽으로 방사한다. 시험실 GPS 중계기는 끈다.
- **슬롯**: 독의 셀 자리. GNSS 는 슬롯마다 받는 신호가 달라 셀 효과와 슬롯 효과를 나눠야 한다(GNSS-정지). IMU 는 슬롯 효과가 없다(IMU-정지 첫 실측).
- **셀 기록 받기**: 시험이 끝나면 셀 저장 기록을 받으면서 셀에서 비운다.

## 2-1. 운영 순서와 단계별 거르기

**QC 시험은 GNSS-정지 → GNSS-이동 → IMU-정지 → IMU-이동 차례로 하고, 앞 시험에서 불합격한 셀은 뒤 시험의 판정에서 뺀다. 펌웨어 시험은 QA 로, 셀마다 하지 않고 펌웨어 버전마다 1회 한다(2026-11-13).** 나쁜 센서 위에서 잰 펌웨어 값은 해석할 수 없기 때문이다(사용자 결정 2026-11-12). 센서 시험 넷(수신 · Raw data)을 먼저, 펌웨어 시험 둘을 뒤에 한다. GNSS-이동을 GNSS-정지 바로 뒤에 둔 것은 GNSS 끼리 묶어 GNSS 수신 모듈을 먼저 다 보기 위해서다. GNSS-펌웨어는 보류라 지금은 IMU-펌웨어까지 돈다.

| 칸 | 내용 |
|---|---|
| 거르기 파일 | 세트마다 하나, `cell-bench/data/qc_gate_<세트>.json`. 셀마다 시험 ID 별로 '합격 · 재측정 · 불합격' 과 날짜 · 근거 폴더 · 이유를 누적한다 |
| 실행기 | 시작할 때 거르기 파일을 읽어 **앞 시험에서 '불합격'한 셀을 판정 대상에서 뺀다**(독에는 있어도 된다). 뺀 셀과 이유를 실행 기록(`run.log`)과 요약(`summary.json` 의 `excluded`)에 남기고, 판정 스크립트와 판정 도구(`protocol_v4.py`)는 그 셀을 건너뛴다. '재측정' 셀은 빼지 않는다. `--include-failed` 로 끈다 |
| GNSS-정지 1차 거르기 | 회차가 끝나면 바로: ① 판정 구간의 실시간 패킷으로 셀마다 **신호 세기(C/N0) 중앙값**과 위치 잡은 패킷 비율을 기록한다(`summary.json` 의 `cn0`) ② 꽂은 행의 셀마다, 위치 잡은 패킷이 50 % 아래(수신 없음 포함)이거나 **(신호 세기 − 회차 효과 − 칸 기준값)이 −3 dB 보다 낮으면** 그 회차에 걸린 것으로 보고 **'재측정'** — 다음 회차에 다른 칸에 꽂아 한 번 더 잰다 ③ 걸린 회차가 **두 번이면 '불합격'**, 재측정에서 걸리지 않으면 '합격' |
| 칸 기준값 · 회차 효과 | **칸 기준값**은 칸마다 신호가 얼마나 세게 들어오는지(칸 효과, 중앙 0)다. 독의 칸에 따라 신호가 −4.6 ~ +5.4 dB 다르고 칸을 뺀 셀 차이는 ±2 dB 안이어서(3절 GNSS-정지 근거 ③), 셀을 칸 몫을 뺀 값으로 비교한다. 값은 기준 파일의 `slot_baseline` 에 조건(감쇠 · 꽂은 행)마다 있다 — 지금은 '감쇠 18 dB · 1 · 3행' 하나. **회차 효과**는 그 회차의 전체 수준으로, 위치를 잡은 셀들의 (신호 세기 − 칸 기준값) 중앙값 하나다. 칸 기준값이 없는 조건(다른 배치 · 감쇠)이나 표에 없는 칸은 **그 회차 같은 행의 다른 셀 중앙값**과 비교하고 결과에 **'임시 기준'** 이라 적는다. 회차가 쌓이면 거르기 파일의 기록으로 칸 기준값을 다시 맞출 수 있다(`python -X utf8 -m motionbench.qc_gate data/qc_gate_<세트>.json` — 값을 보여 주기만 하고, 기준 파일은 사람이 고친다) |
| IMU-정지 · IMU-이동 | 판정 스크립트(`imu_static_judge.py` · `imu_move_judge.py`)가 끝날 때 아래 합격 기준 0.1 로 '합격 · 불합격' 을 적는다. 재측정 단계는 없다 |
| 숫자 | 기준 파일 하나 `cell-bench/motionbench/criteria/qc_tests.json` 에서 읽는다. GNSS-정지의 3 dB 는 아래 합격 기준 (버전 0.1) 의 3 dB 와 같은 값이고, 위치 잡은 비율 50 % 는 제안값이다. 기준 버전을 바꾸면 이 문서와 그 파일을 함께 고친다 |
| 함께 돌릴 때 | 묶음 실행기 안에서는 앞 시험의 판정이 아직 없으므로 시작할 때의 거르기 파일로만 뺀다. 센서 시험 결과로 펌웨어 시험을 거르려면 **센서 시험 → 판정 스크립트 → 펌웨어 시험** 차례로 나눠 돈다. 묶음 실행기는 장면을 바꾸는 GNSS-이동을 맨 끝에 돌린다(다른 레일 시험은 정지 장면 아래에서 돌아야 한다) — 거르기 파일은 시작할 때 한 번만 읽으므로 이 실행 차례가 거르기 결과를 바꾸지 않는다 |

이 거르기는 회차 하나로 내리는 1차 판단이다. GNSS-정지의 셀 · 슬롯 · 회차 효과 분해(3절 판정 방법)는 회차가 쌓인 뒤 따로 본다. 셀 하나가 독 전체를 통틀어 몇 회차 걸렸는지는 거르기 파일의 `rounds` 에 남는다.

## 실행기와 판정 스크립트

각 시험을 돌리는 실행기와 판정 스크립트는 [`cell-bench/tools/qc_tests/`](../../cell-bench/tools/qc_tests/README.md)에 있다. 시험마다 실행기가 하나씩 있고(`gnss_static_run.py` · `gnss_move_run.py` · `imu_static_run.py` · `imu_move_run.py` · `imu_fw_run.py`, GNSS-펌웨어는 보류라 없다), 여러 시험을 이어 돌릴 때는 묶음 실행기 `qc_bundle.py --tests IMU-MOVE,IMU-FW` 가 준비와 셀 기록 받기를 한 번만 한다. GNSS-정지 은 독 배치와 장면 구간이 달라 혼자 돈다. 기록은 `cell-bench/data/<시험 ID>_<날짜>/` 에, 단계별 거르기 결과는 `cell-bench/data/qc_gate_<세트>.json` 에 쌓인다. 시험별로 어느 파일을 쓰는지, 어떤 파이썬으로 띄우는지는 그 폴더의 README 가 정본이다.
