# 상태 먼저 규칙 — 바깥으로 나가는 행동 전에 지금 상태를 본다

> 한 줄 요지: **머지·PR·배포·메시지 발송 전에 지금 상태를 조회한다.** 이미 된 일은 다시 하지 않고, 열려 있는 것은 새로 만들지 않고 이어 쓴다. 기다릴 때는 무엇을 언제까지 기다리는지 먼저 말한다.

## 1. 행동 전 조회

| 하려는 행동 | 먼저 조회 | 이미 돼 있으면 |
|---|---|---|
| PR 머지 | `merged` 여부 | 머지하지 않고 배포 상태로 넘어간다 |
| PR 열기 | 같은 base 로 열린 PR | 새로 열지 않고 그 PR 에 커밋·본문 줄을 더한다 |
| 배포 PR(develop→master 등) | 열린 배포 PR | **배포 PR 은 하나.** 본문의 "함께 나가는 변경" 목록에 한 줄 더한다 |
| 배포 완료 보고 | 실행(run) 상태 | 진행 중이면 예상 시각을 말하고 예약 확인(`send_later`) |
| Slack·메일 발송 | 이미 보냈는지 | 다시 보내지 않는다 |

- **사용자가 "~했어"라고 하면** 그 행동을 하지 않는다. 상태만 조회해 다음 단계로 간다. 이미 띄운 승인 창이 있으면 "눌러도 바뀌는 것 없음"을 알린다.

## 2. 기다릴 때

| 해야 할 것 | 하지 않을 것 |
|---|---|
| 시작할 때 한 줄: 무엇을 · 언제쯤 끝나는지 · 링크 | 말없이 몇 분씩 도구만 돌리기 |
| 결과가 나올 때 다시 보게 예약 | 같은 조회를 짧은 간격으로 반복 |
| 볼 수 없는 신호(Slack 답장 등)는 처음에 밝힘 | 볼 수 없는데 기다리는 척 |

## 3. 하위 세션에 일을 넘길 때

부모 세션이 하위 세션(`create_session`)을 만들면 프롬프트에 아래를 싣는다.

| 실을 것 | 예 |
|---|---|
| 이미 열린 PR · 배포 PR 번호 | "운영 배포 PR 은 #56, 새로 열지 말 것" |
| 머지·배포를 누가 누르는지 | "develop 머지와 master 머지는 건우 님" |
| 결과를 돌려줄 곳과 막혔을 때 | 부모에 `send_message`. 거부되면 사용자에게 링크를 바로 적는다 |
| 하위 세션이 볼 수 없는 것 | Slack 답장, 다른 세션의 대화 |

## 4. 태어난 사고 (2026-11-11, FitOps 재고 이동 엑셀)

| 일어난 일 | 맞는 것 |
|---|---|
| 사용자가 "dev 는 머지했어"라고 한 PR 에 하위 세션이 머지 승인 창을 띄움 | 머지 전 `merged` 조회 |
| 하위 세션이 운영 배포용 PR 을 새로 열 계획 | 열린 배포 PR #56 에 이어 씀 |
| 배포 확인 중 5분간 말이 없어 사용자가 "진행 중이야??" | 시작할 때 예상 시각 한 줄 |
| 하위 세션의 부모 보고가 거부돼 사용자가 링크를 옮김 | 거부되면 사용자에게 바로 링크 |
