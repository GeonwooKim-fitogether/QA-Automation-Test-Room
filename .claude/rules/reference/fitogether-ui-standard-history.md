# 사내 공통 화면 기준 v1 — 부록: 결정 경위와 적용 때 난 사고

> 이 파일은 [`../fitogether-ui-standard.md`](../fitogether-ui-standard.md)의 부록이다. 규범은 코어 파일에 전부 있고, 여기에는 기준이 어떻게 정해졌는지와 Fitstack 에 적용할 때 실제로 일어난 일만 있다. 자동 로드되지 않는다.

## 어디서 시작했나

2026-11-05, 회사 브랜드 문서 가이드(`Fitogether_AI_Brand_HTML_Guide_v1`)가 공유됐다. 원래는 "AI 가 만드는 HTML 문서"의 규칙이었지만, 공유한 의도는 **사내 시스템(Fitstack·FitOps·FitDeal)이 늘어나면서 전체 룩앤필을 맞추는 것**이었다. 그래서 가이드를 그대로 옮기지 않고, 앱 화면에 맞는 것만 골라 쓰기로 했다.

출발점에서 세 앱은 서로 달랐다(2026-11-06 실측).

| 앱 | 화면 도구 | 서체 | 주색 | 브랜드와의 거리 |
|---|---|---|---|---|
| FitOps | shadcn + Tailwind 4 | Pretendard | `#12747e`, 상태 톤 7쌍 | 이미 브랜드 팔레트 기반 |
| FitDeal | shadcn + Tailwind 4 | Noto Sans KR | 남색 `#1a2c34`, 모서리 6 | 중간 |
| Fitstack | antd 5 | Noto Sans KR | `#2b7a78`, Ground Control 종이색 `#f1eee7` | 가장 멀다 |

화면 도구가 다르므로(antd 와 shadcn) **앱끼리 나눠 쓰는 단위는 컴포넌트가 아니라 토큰**(색·서체·모서리·상태색의 뜻)이 됐다.

## 어떻게 정했나 — 그림을 보며 하나씩

2026-11-06 하루 동안, 논점마다 현재 모습과 안별 모습을 그린 선택판(https://claude.ai/artifact/HAGaccT1Ytwv9uQn7Tq2ds)을 보여 주며 하나씩 물었다.

1. **서체 = Pretendard.** 공식 서체 Area 는 한글이 없고, Pretendard 와 Noto Sans KR 의 한글은 같은 뿌리라 바뀌는 것은 영문·숫자뿐이었다.
2. **강조색 = 잉크.** 누르는 것과 고른 것은 잉크, 청록은 링크와 작은 표식에만 쓴다. 탑바는 흰 바탕에 가는 선.
3. **상태색 = 일곱 톤, 채움**(FitOps 의 톤 값, 진행은 주황). 추천안이던 다섯 색은 채택되지 않았다.
4. **화면 틀 = 그대로.** 시스템 이름·앱 전환 메뉴도 넣지 않는다.
5. **메뉴 언어 = 앱마다 한 언어.** FitOps 의 Guide·Home·Admin 이 가이드·홈·관리자로 바뀐다.
6. **아이콘 = 그대로.** Fitstack antd, FitOps Remix.
7. **작은 기본값** — 모서리 4px, 카드 그림자 없음, 잉크 포커스, 바탕·선·글자 값, 날짜 형식, **Fitstack Ground Control 테마 폐기**(예전 결정을 뒤집음).

**사용자는 추천안을 그대로 받지 않았다** — 넷 중 셋을 다르게 골랐다. 그래서 화면 결정은 추천을 내밀고 승인받는 방식이 아니라, 그림을 보여 주며 하나씩 묻는 방식으로 받는다.

## 시안 형식 — 무엇이 거절되고 무엇이 통했나

Fitstack 적용 시안을 처음에는 실제 화면의 전후 스크린샷으로 보여 줬는데, "이런 식으로 보여주지 말고 html 로 진짜처럼"이라며 거절됐다. 실제 앱을 픽스처(가짜 데이터) 모드로 띄워 **클릭되는 정적 HTML** 로 뜨고, 고를 것은 화면에 떠 있는 선택 패널로 바꿔 보게 한 시안(https://claude.ai/artifact/UXEtvFvcHfMke8J9FbCrSL)이 통했다. 이 시안으로 KPI 타일 모양, 연한 표 머리글, 상태 배정, 로고 크기(22px 은 "너무 작다" → 28px), 제목 줄을 하나씩 확정했다.

같은 날 시안 없이 개발부터 들어갔다가 "먼저 디자인 시안부터 나한테 확인해야 하는 거 아니야?"라는 지적도 받았다. 화면 작업의 순서를 시안 → 사용자 확인 → 개발로 못 박은 이유다.

## Fitstack 적용과 그때 난 사고 (2026-11-06 ~ 11-07)

기준은 fitogether-org/Fitstack PR #484 로 적용됐다. 이 PR 은 색 리터럴 톱니 검사를 새로 넣고, 더 쓰지 않는 Ground Control 토큰 셋(`--void`·`--void2`·`--signal`)을 지웠다.

**#484 가 머지된 지 13분 뒤, 나란히 만들어진 #485 가 머지됐다.** #485 는 #484 가 지운 토큰과 옛 청록 색을 쓰고 있었다. 두 PR 은 각자의 base 에서는 검사가 초록이었지만, #485 는 #484 위에서 다시 검사받지 않은 채 머지됐다. 그래서 main 의 검사가 실패했고, 두 PR 모두 배포가 건너뛰어졌다. 검사가 잡은 것은 실제 화면 결함이었다 — 머리글 바탕이 사라져 흰 글자가 보이지 않았다.

PR #486 이 부딪힌 곳을 기준 토큰으로 고쳤고, 2026-11-07 00:58 KST 에 배포가 성공해 Fitstack 의 기준 v1 이 배포완료됐다. 이 사고가 코어 5절의 "토큰을 지우거나 검사를 새로 넣는 PR 은 머지 전에 겹치는 열린 PR 을 확인한다"는 한 줄의 근거다. 원 기록은 Fitstack `docs/lessons.md` 의 2026-11-07 항목이다.
