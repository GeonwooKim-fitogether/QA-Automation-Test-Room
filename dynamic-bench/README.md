# dynamic-bench — 리니어 모터 기반 동적 QA · 출하 QC 시스템

정답 모션(모터 엔코더 ≈ 1 µm)을 만들어 셀(스포츠 웨어러블 센서 기기) 데이터 — raw(라이브 패킷) · 추출(FTG 파일) · iOS LiveApp 화면 — 이 맞는지 **숫자로** 판정하는 시스템입니다. **QA**(표본 심층 검증: 정확도 → 내구성)와 **출하 QC**(들어오는 셀 전수 선별)를 가르며, QA 의 결과가 QC 의 합격 기준이 됩니다. cell-bench(같은 저장소) 위에 모션 엔진 프로세스 하나를 더하는 구조입니다.

- 구동부: Panasonic MINAS-A6BL LINEAR 드라이브(MBDLN25BL) + 리니어 모터, EtherCAT 연결. 목표 5 모듈(모터 · 드라이브 5대, 지금 1대)
- 제어 PC: 3 QA 제어 PC 2 (DELLXPS15-PCW, Windows 11, Python 3.11.9) — 모듈 1 전용, LiveHub 별도
- 운영 방식: 봇(Claude Code)이 시스템을 돌리고 결과를 보고하며, 사람은 감독·검토·결정만 합니다. 출하 QC 는 별도 작업자가 작업자 화면으로 돌립니다.
- 제어 프로그램: `cell-bench/run_motion.py` + `cell-bench/motionbench/` 를 새로 작성합니다. 통신 계층은 pysoem. 전임자(조시우)의 SOEM 기반 프로그램은 하드웨어 참고 자료로만 읽고, 기반 코드로 쓰지 않습니다.

## 안전 원칙

모터 구동(서보 온, OP 전환, Controlword 송신)은 **사용자가 현장에 있을 때만** 합니다. M1 뒤 사용자가 방향 부호·소프트 리미트·속도 상한을 승인한 뒤에만 움직이고, 물리 안전장치(리미트 센서 · STO 비상정지 · 가드)가 생기기 전에는 입회 시에만 움직입니다. 최종 목표는 24시간 무인 운전입니다.
