# 보고 양식 규칙 · 합의한 틀과 합의한 말로만 보고한다

> 한 줄 요지: **보고는 사용자와 합의한 양식(표 틀)과 합의한 말로만 쓴다.** 표는 대상 하나에 하나, 칸 하나에 값 하나, 칸에는 핵심어와 숫자만 넣는다. 합의한 말은 저장소의 용어표(`.claude/terms.json`)가, 합의한 양식은 양식 파일(`.claude/report-formats/<양식 이름>.json`)이 담고, 두 훅이 그 밖의 말과 표를 막는다. 양식이 없는 새 종류의 보고는 양식부터 보여 주고 합의한다.

여기서 "보고"는 사용자에게 상황을 알리려고 내는 표 · 현황판 · 브리프 · 시험 현황을 말한다. 채팅의 설명 답변과 저장소의 설명 문서는 [communication 규칙](./communication.md) 1(완전한 문장)을 그대로 따르고, 이 규칙은 **보고 안의 표와 낱말**에 적용된다. 이 규칙이 태어난 사고(하루 동안 같은 지적이 반복되고 장비 운전이 0회였던 일)는 [부록](./reference/report-format-history.md)에 있다.

## 1. 원칙 14개

| 번호 | 원칙 | 지키는 법 |
|---|---|---|
| 1 | 틀 고정 | 보고할 때마다 표를 새로 만들지 않는다. 다 못 채워도 합의한 틀은 그대로 두고 빈 칸으로 남긴다 |
| 2 | 표 하나 | 한 장(한 대상)에 표 하나. 대분류 · 중분류로 나누고, 칸 하나에 값 하나 |
| 3 | 문장 금지 | 칸에는 핵심어와 숫자만. 한 칸은 2줄까지 |
| 4 | 정한 말 그대로 | 풀어 쓰기 · 덧붙이기 · 바꿔 부르기 · 혼자 지은 말을 쓰지 않는다. 정한 말이 없으면 묻는다 |
| 5 | 문서에서 읽기 | 기준 문서가 있는 값(조건 · 절차 · 기준)은 기억으로 다시 쓰지 않고 그 문서에서 그대로 읽는다. 근거를 못 대는 내용은 넣지 않는다 |
| 6 | 목적 · 목표 먼저 | 순서는 목적, 목표, 조건, 절차, 기준, 결과, 이슈, 다음 |
| 7 | 합의 · 진행 구분 | 사용자와 합의가 끝난 것과 작업 · 시험이 끝난 것을 상태 칸에 따로 표시한다 |
| 8 | 조건은 모듈, 대상은 조합 | 한 칸에 조건 두 개를 섞지 않는다. 조건이 바뀌면 기존 모듈을 고치지 않고 새 모듈 값을 더한다 |
| 9 | 대상별 한 장 | 목표는 그 대상을 완성하는 것. 위에서부터 하나씩 점검한다 |
| 10 | 하나씩 끝내기 | 미완료를 남긴 채 이것저것 손대지 않는다 |
| 11 | 시키지 않은 곳에 넣지 않기 | 자리가 애매하면 묻는다 |
| 12 | 주어 먼저 | 대상 이름을 크게 먼저 둔다. 결론은 같은 줄 오른쪽 끝에 한 줄 |
| 13 | 합의한 용어 · 모듈은 장치로 강제 | 용어표 `.claude/terms.json` 과 훅 `terms-guard.py` (2절) |
| 14 | 보고 양식은 합의로 정하고 합의로 바꾼다 | 양식 파일 `.claude/report-formats/` 와 훅 `report-format-guard.py` (3절) |

4번의 금지 예(2026-11-13 사례): `원값`(대신 `Raw data`), 정한 이름 대신 묶음을 부르는 `조합`, `모터 없음`, `판`, `정본`. 이런 말은 저장소마다 다르므로 규칙 파일이 아니라 그 저장소의 용어표에 적는다.

## 2. 용어표와 `terms-guard.py` · 정한 말 밖의 말을 막는다

저장소마다 `.claude/terms.json` 을 둔다. 이 파일은 **그 저장소 소유**다(창고에서 내려오지 않는다). 견본은 창고의 [`templates/report-formats/terms.example.json`](../../templates/report-formats/terms.example.json) 이다.

```json
{
  "agreed": [
    {"term": "Raw data", "meaning": "가공하지 않은 측정 기록", "source": "시험 문서 1-1절"}
  ],
  "banned": [
    {"word": "원값", "instead": "Raw data", "decision": "2026-11-13 사용자 지시"},
    {"word": "판", "pattern": "(?<![가-힣])판(?![가-힣])", "decision": "2026-11-13 사용자 지시"}
  ],
  "exclude": ["docs/lessons.md"]
}
```

| 칸 | 뜻 |
|---|---|
| `agreed` | 정한 말과 그 출처. 훅은 읽지 않고, 사람과 세션이 대조할 때 본다 |
| `banned[].word` | 쓰지 않기로 한 말. 기본은 글자 그대로 찾는다 |
| `banned[].pattern` | 한 글자 말처럼 다른 낱말 안에 섞이는 말은 정규식으로 좁힌다(`판` 이 `판정` 에 걸리지 않게) |
| `banned[].instead` | 대신 쓸 말. 비워 두면 훅이 "사용자에게 물으라"고 알린다 |
| `exclude` | 검사하지 않을 저장소 안 경로(glob). 금지어를 기록으로 남기는 파일을 둔다 |

훅이 보는 곳과 하는 일은 이렇다.

| 도구 | 검사하는 글 |
|---|---|
| `Write` · `Edit` · `NotebookEdit` | 저장소 안에 쓰는 내용. 저장소 밖(메모리 · 임시 폴더)은 보지 않는다 |
| `Artifact` | 게시하는 파일과 함께 올리는 파일. 위치와 상관없이 본다 |

금지한 말이 있으면 **막고**, 찾은 말과 대신 쓸 말을 알린다. 용어표 자신, `.claude/hooks/` 아래, `exclude` 경로는 보지 않는다. **용어표가 없는 저장소에서는 아무 일도 하지 않는다.** 금지를 푸는 방법은 용어표에서 그 항목을 지우는 것 하나뿐이고, 그것은 커밋으로 남는다.

## 3. 보고 양식과 `report-format-guard.py` · 합의한 표로만 보고한다

### 3-1. 양식 파일

저장소마다 `.claude/report-formats/<양식 이름>.json` 에 합의한 양식을 둔다(그 저장소 소유). 견본은 창고의 [`templates/report-formats/test-status.json`](../../templates/report-formats/test-status.json) 이다.

| 칸 | 뜻 |
|---|---|
| `name` · `title` | 양식 이름(파일 이름과 같다)과 보고 종류 |
| `version` | 합의할 때마다 1씩 올린다 |
| `header` | 머리의 배치. 대상 이름은 크게 왼쪽, 결론은 같은 줄 오른쪽 끝 |
| `columns` | 표의 칸 이름과 순서 |
| `categories` | 대분류와 순서. 대분류 칸에는 이 값만 이 순서로 온다 |
| `cell` | 한 칸의 줄 수 상한(기본 2) |
| `history` | 버전마다 날짜 · 바뀐 것 · 합의한 사람 · PR |

### 3-2. 쓰는 법 · 합의 먼저, 합의한 양식으로만, 바꿀 때도 합의

1. **새 종류의 보고**는 양식 파일 안을 먼저 사용자에게 보여 주고 합의한다. 합의하기 전에는 그 종류의 보고를 만들지 않는다.
2. **같은 종류의 보고**는 그 양식으로만 쓴다. 생성기 견본 [`report-render.py`](../workflows/report-render.py) 가 양식과 값 파일을 읽어 표를 그리고, 표에 `data-report-format` 과 `data-report-version` 을 붙인다.
3. **양식을 바꿀 때**는 바꾼 안을 보여 주고 합의한 뒤 `version` 을 올리고 `history` 에 한 줄 더한다. 양식 파일의 변경은 PR 로만 한다.

### 3-3. 훅이 막는 것

`report-format-guard.py` 는 `Artifact` 게시와 `.html` 파일 `Write` 때 HTML 안의 `<table>` 을 본다. **양식 폴더가 없는 저장소에서는 아무 일도 하지 않는다.**

| 표의 상태 | 판정 |
|---|---|
| `data-report-format` 이 없다 | 막는다. 새 종류의 보고면 양식부터 합의하라고 알린다 |
| 없는 양식 이름이다 | 막는다 |
| 버전이 양식 파일의 `version` 과 다르다 | 막는다 |
| 머리글 칸 이름 · 순서가 `columns` 와 다르다 | 막는다 |
| 대분류 칸 값이 `categories` 밖이거나 순서가 다르다 | 막는다 |
| 한 칸이 `cell.max_lines` 줄을 넘거나 문장으로 끝난다(`다.` · `니다` · `요.`) | 막는다 |
| `data-report-format="none"` | 통과한다. 보고가 아닌 표(부록의 원자료 등)에만 쓴다 |

## 4. 장치가 덮지 못하는 것

- **훅은 자기가 보는 도구만 본다.** 셸로 파일을 만들거나 채팅 답변에 표를 쓰는 것은 보지 못한다. 채팅의 보고 표도 이 규칙을 따르는 것은 세션의 몫이다.
- **`none` 표시는 사람의 정직에 기댄다.** 보고 표에 `none` 을 붙여 검사를 피하는 것은 규칙 위반이며, 훅은 그것을 가려내지 못한다.
- **원칙 5 · 6 · 7 · 9 · 10 · 11 · 12 는 글로만 있다.** 값이 기준 문서와 같은지, 하나씩 끝냈는지, 시키지 않은 곳에 넣었는지는 훅이 판단할 수 없다. 6 · 7 · 12 는 양식 파일의 `categories` · `columns` · `header` 에 담아 생성기가 지키게 할 수 있지만, 머리 배치는 훅이 검사하지 않는다.
- **용어표에 없는 새 말은 막지 못한다.** 혼자 지은 말은 처음 나올 때 사람이 잡고, 잡힌 말을 용어표에 더해야 다음부터 막힌다.
- **훅이 아예 실리지 않는 세션이 있다**(여러 저장소를 한 폴더에 여는 세션, 2026-08-17 실측). 그런 세션에서는 이 규칙을 Claude 가 스스로 지킨다.

## 적용 범위

- 모든 저장소의 모든 세션의 보고에 적용된다. 브리프의 장 양식은 [`ceo-brief`](../skills/ceo-brief/SKILL.md) 3-3절이 정하고, 겹치는 부분(낱말 · 칸 · 표 틀)은 이 규칙을 따른다. 충돌하면 이 규칙이 이긴다.
- 단일 원본은 창고(Template-repository)의 `.claude/rules/report-format.md` 이며, 강제 장치는 `.claude/hooks/terms-guard.py` · `.claude/hooks/report-format-guard.py` 와 `.claude/settings.json` 의 `PreToolUse` 설정이다.
- 용어표(`.claude/terms.json`)와 양식 파일(`.claude/report-formats/`)은 저장소 소유라 동기화 대상이 아니다.
- 훅의 판단 시험: `python3 .claude/hooks/terms-guard.test.py`, `python3 .claude/hooks/report-format-guard.test.py`.
